The problem

Thousands of small sites still run PHP 5.x-era code

Schools, clinics, and local news outlets in emerging markets keep running code nobody fully remembers anymore — and modernizing it by hand is slow, risky, and usually gets skipped.

🗄️

Removed mysql_* calls

Deprecated in PHP 7, removed entirely — old code simply stops running.

💉

SQL injection

Queries built by concatenating request input directly into SQL strings.

🔓

Weak MD5 passwords

Passwords hashed (or compared) with MD5/SHA1 instead of password_hash().

🛡️

No CSRF protection

State-changing forms with no token — trivially forgeable requests.

📤

Unescaped output (XSS)

User input echoed straight into HTML with no escaping.

The solution

A deterministic six-stage pipeline

Every fix is a human-reviewable diff before anything is written — nothing changes silently.

1

Scan

16 rules find SQLi, XSS, weak hashing, CSRF gaps & more

2

Plan

Findings prioritised: auto-fixable → assisted → manual

3

Fix

Safe rewrites, reviewable as a unified diff first

4

Test

PHPUnit regression tests generated from real findings

5

Verify

Re-scans the fixed copy, compares before vs. after

6

Report

One self-contained HTML report, dark-mode aware

Detection rules

16 rules covering the common PHP 5→8 hazards

Dependency-free, line-oriented regex rules — no tree-sitter, no PHP toolchain required to scan.

LL001critical

Removed mysql_* functions

✅ Auto-fix → PDO
LL002critical

SQL built by concatenating request input

✅ Auto-fix → parameterized query
LL003high

Unescaped output of user input (XSS)

✅ Auto-fix → e() escaping
LL004critical

Weak MD5/SHA1 password hashing

✅ Auto-fix → password_hash()
LL005high

Missing CSRF token on state-changing forms

✅ Auto-fix → token + verification
LL006high

extract($_REQUEST) / register-globals style

🚩 Assisted — human decision
LL007medium

Deprecated functions (ereg*, split…)

✅ Auto-fix → modern equivalents
LL008medium

✅ Partial auto-fix
